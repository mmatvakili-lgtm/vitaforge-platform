# شکاف‌های API: OPEN-009، OPEN-010، OPEN-011

هیچ‌کدام در این مرحله تغییر نکرد؛ هر مورد نیاز به تصمیم دارد. تغییر spec فقط پس از تصمیم و با تست پذیرش.

## OPEN-009: تحویل Export — بسته شد (API-PRIV-006)

- **انجام شد:** `GET /privacy/export/{request_id}` فقط برای مالک، ۲۴ ساعت اعتبار، پس از آن ۴۱۰ و حذف نسخه‌ی ذخیره‌شده؛ شامل داده‌ی تغذیه؛ بدون رمز/توکن؛ با حذف حساب نسخه‌ها هم پاک می‌شوند. تست: `devserver/tests/test_batch_b.py`.
- **متن اولیه‌ی شکاف (برای سابقه):**

- **فعلی:** `POST privacy/export` داده را برمی‌گرداند؛ endpoint دانلود/فایل ندارد.
- **مورد انتظار:** کاربر خروجی قابل دانلود و محدود به خودش بگیرد.
- **پیشنهاد:** پاسخ همگام فعلی را نگه دار (MVP)؛ `GET privacy/export/{id}` با انقضا در فاز بعد.
- **تغییر:** spec (endpoint جدید) و پیاده‌سازی.
- **پذیرش:** کاربر B نمی‌تواند export کاربر A را بخواند؛ پاسخ با اسکیما منطبق؛ بعد از انقضا 410.

## OPEN-010: پیگیری ایمنی پس از توقف به‌علت درد

- **فعلی:** پس از `aborted_reason=pain` فیلد `safety_followup` ارسال نمی‌شود چون ناحیه درد ثبت نمی‌شود.
- **مورد انتظار:** توصیه محتاطانه و ارجاع، بدون تشخیص.
- **پیشنهاد:** افزودن فیلد اختیاری `pain_region` (enum نواحی) به finish؛ در نبود آن، پیام عمومی ارجاع.
- **تغییر:** spec و `workouts.finish`.
- **پذیرش:** با `pain` پاسخ شامل `safety_followup` است؛ بدون ناحیه پیام عمومی؛ هیچ تشخیص بالینی در متن نیست؛ متن نیاز به بازبینی متخصص (OPEN-003).

## OPEN-011: ناهماهنگی‌های spec و پیاده‌سازی

| مورد | فعلی | پیشنهاد |
|---|---|---|
| ADM-003 نقش‌ها | spec و `ROLE_FOR_TARGET` متفاوت | spec اصلاح شود تا نقش هر گذار را بگوید (ایمنی‌محور) |
| ADM-007 | spec ایجاد grant توسط ادمین؛ پیاده‌سازی grant توسط کاربر | تصمیم محصولی لازم؛ پیش‌فرض: grant فقط کاربر، ادمین 403 |
| ADM-005 | فیلد تأیید ندارد (`notes`) | افزودن `signoff_ref` |
| enum رضایت | نوع `privacy` نیست | افزودن به enum |
| PROG-002 | 402/429/503 پیاده نشده | پیاده‌سازی با سهمیه |
| ONB 5–14 | 422 | پیاده‌سازی یا حذف از spec |
| ثبت‌نام با تلفن | پشتیبانی نمی‌شود | حذف از spec یا Deferred |
| `stop_criteria_key` | ارائه نمی‌شود | افزودن به پاسخ برنامه |

**وضعیت (۲۰۲۶-۱۱-۱۴):**
- ADM-005: بسته شد؛ فیلد `signoff_ref` اضافه شد و `notes` برای سازگاری پذیرفته می‌شود (تست در `test_behaviour.py`).
- ADM-003 / ADM-007: بدون تغییر رفتار؛ تصمیم مهندسی: پیش‌فرض پیشنهادی (ایمنی‌محور؛ grant فقط توسط کاربر) همان‌طور که پیاده شده می‌ماند.
- enum رضایت `privacy`: **Deferred** تا متن حقوقی حریم خصوصی (OPEN-002) آماده شود؛ افزودن enum بدون سند معتبر بی‌معنی است.
- PROG-002 (۴۰۲/۴۲۹/۵۰۳): **Deferred**؛ وابسته به اشتراک/پرداخت (OPEN-001/005).
- ONB 5–14، ثبت‌نام با تلفن، `stop_criteria_key`: **Deferred**؛ هر سه به محتوای بالینی/تصمیم محصول وابسته‌اند و رفتار فعلی (۴۲۲ / `phone_registration_not_supported` / نبودن فیلد) عمداً امن است.

**پذیرش کلی:** Harness بدون استثنا؛ هر تغییر spec با تست رد/قبول و ثبت در Decision Registry.
