## 1. اهداف و دامنه
Safety Core تنها مرجع تصمیم ایمنی برای: نمایش/عدم نمایش هر برنامه، هر حرکت، هر جایگزین، و هر خروجی AI. این سند ورودی/خروجی، اولویت‌ها، حالت‌های توقف، مسیرها و گردش حاکمیت را تعریف می‌کند.

### 1.1 اصول
| شناسه | اصل |
|---|---|
| SAF-P01 | Safety Core مستقل از LLM، شبکه و Provider خارجی. |
| SAF-P02 | تصمیم قطعی (deterministic)، قابل بازتولید، نسخه‌دار. |
| SAF-P03 | Fail-safe: خطا/ابهام/داده ناقص ← حالت محافظه‌کارانه‌تر (عدم نمایش یا پرسش). |
| SAF-P04 | محدودیت متخصص > قاعده عمومی > پیشنهاد AI. |
| SAF-P05 | هیچ تشخیص، هیچ وعده درمان، هیچ پروتکل اختراعی. |
| SAF-P06 | هر تصمیم ثبت و قابل ممیزی. |
| SAF-P07 | قابلیت ایمنی رایگان است (DEC-005). |

## 2. جایگاه معماری
```
UI/API → Orchestrator (workout_engine / ai / nutrition)
              │  (SafetyRequest)
              ▼
        ┌───────────────┐
        │  Safety Core  │  ← قوانین نسخه‌دار (DB، read-only در runtime)
        └──────┬────────┘
               │ SafetyDecision
               ▼
   فقط حرکات/برنامه‌های Approved به UI می‌رسند
```
- Safety Core یک پکیج دامنه بدون وابستگی به DRF/LLM/HTTP است.
- هیچ ماژولی نمی‌تواند حرکتی را به کاربر برگرداند مگر دارای `SafetyDecision.status ∈ {ALLOW, ALLOW_WITH_MODIFICATION}` و `decision_id` معتبر باشد.
- Validator پس از LLM (سند 8) هر خروجی را با Safety Core دوباره تطبیق می‌دهد.

## 7. مسیرهای محدودیت جسمانی

### 7.1 مسیر A — سابقه مشکل، بدون درد فعال
- پیش‌شرط: کاربر درد فعال ندارد، هشدار ندارد، و محدودیت‌ها ثبت شده.
- اگر محدودیت **متخصص** مکتوب وجود دارد: فیلتر سخت (SAF-R006).
- اگر فقط خوداظهاری وجود دارد: ناحیه «احتیاط» می‌شود؛ فقط حرکاتی که برچسب سازگار با آن ناحیه دارند (دارای `published` و بازبینی) مجازند.
- جایگزین: مطابق الگوریتم §9؛ اگر معتبر نیست → اعلام «جایگزین مناسب یافت نشد».
- بازبینی دوره‌ای: `review_due_at` (بازه توسط EXP).
- عبارت «مشکل کمر» به‌تنهایی کافی نیست: مجموعه پرسش‌های سند مادر §9 (درد فعلی؟ محل؟ شروع؟ انتشار؟ بی‌حسی/ضعف؟ تشخیص؟ محدودیت پزشک؟ مجوز؟ عوامل تشدید؟) اجباری است. ورودی‌ها در `symptom_records`. اگر پاسخ ناقص → `NEEDS_INFO`.

### 7.2 مسیر B — درد جدید/نامشخص بدون تشخیص (DEC-116، DEC-124)

**اصل:** مسیر B تشخیص نیست و اجازه خودکار تمرین درمانی نیست. ساختار فنی زیر کامل است؛ **محتوای بالینی هر گام Draft/Pending Review** است (EXP-001، EXP-002، EXP-011).

#### 7.2.1 ماشین حالت
```
B0 ورود (درد جدید/نامشخص ثبت شد)
 → B1 غربالگری هشدار + پرسش‌های ناحیه‌ای [EXP-001/002]
     ├─ هشدار مثبت ........................ B2 STOP_AND_REFER (فوری/غیرفوری طبق قاعده)
     ├─ پاسخ ناقص ......................... NEEDS_INFO (بازگشت به B1)
     └─ هشدار منفی ........................ B3
 → B3 تعیین «ناحیه درگیر» و «ناحیه‌های غیرمرتبط» (جدول نگاشت ناحیه [EXP-003])
     ├─ ناحیه درگیر: هیچ تمرین مرتبط، هیچ برنامه درمانی، توصیه ارزیابی متخصص
     └─ ناحیه‌های غیرمرتبط: فقط اگر قاعده منتشرشده (published) وجود دارد → B4؛ در غیر این صورت → B5
 → B4 فعالیت محدود (Restricted Activity) برای نواحی غیرمرتبط، با پایش هر جلسه
 → B5 بدون برنامه + ارجاع + یادآوری بازبینی
 → B6 ارزیابی مجدد (زمان‌بندی ‹EXP›) → بازگشت به B1 یا خروج (§7.2.6)
```

#### 7.2.2 فعالیت‌های قابل‌ارائه
| دسته | وضعیت | شرط |
|---|---|---|
| تمرین ناحیه درگیر (از جمله «تمرین اصلاحی/درمانی») | **ممنوع** | همیشه |
| تمرین نواحی غیرمرتبط با حرکات `published` و برچسب «بدون بارگذاری ناحیه درگیر» | مشروط (B4) | قاعده منتشرشده نگاشت ناحیه + بدون هشدار + هر جلسه Check-in آنلاین |
| «فعالیت عمومی کم‌خطر» (مانند فعالیت هوازی سبک) | **تعریف نشده** | تا تأیید EXP-011 فعال نیست؛ فقط در محیط آزمایشی با برچسب «غیرمصوب» |
| آموزش عمومی غیرتشخیصی (متن بازبینی‌شده) | مجاز پس از EXP-008 | بدون ادعای علت/درمان |

#### 7.2.3 علائم/رویدادهای توقف مسیر
هر یک از موارد زیر → `STOP_AND_REFER` و خروج از B4: مثبت‌شدن هر علامت هشدار (EXP-001)، تشدید غیرعادی حین/بعد جلسه، انتشار جدید درد یا علائم عصبی جدید، پاسخ «بدتر شده» در Check-in، تداوم/تکرار بیش از آستانه ‹EXP›.

#### 7.2.4 محدودیت‌های اجباری
- فقط آنلاین؛ هیچ ذخیره آفلاین داده درد (DEC-004).
- هیچ پیام تشویق به تحمل درد (SAF-M05).
- هیچ پیشرفت خودکار بار در B4 (SAF-R010 + قفل پیشرفت).
- سقف شدت/حجم در B4: ‹EXP-011›؛ تا تعیین، مقدار پیش‌فرض «بدون برنامه» (B5).
- هر تصمیم با `rule_set_version` ثبت می‌شود.

#### 7.2.5 داده‌های لازم از کاربر (فرم B1)
ناحیه و سمت؛ زمان شروع؛ روند (بهتر/ثابت/بدتر)؛ شدت خوداظهاری (مقیاس ‹EXP›)؛ ماهیت/عوامل تشدید و تسکین؛ ضربه/حادثه اخیر؛ علائم عصبی/عمومی (فهرست هشدار EXP-001)؛ تشخیص یا توصیه قبلی؛ بارداری/شرایط خارج از دامنه (DEC-121). ذخیره: `symptom_records`/`pain_logs` با برچسب «خوداظهاری» (هرگز تشخیص).

#### 7.2.6 شرایط بازگشت به مسیر عادی
بازگشت فقط با یکی از دو راه:
1. **ثبت ارزیابی/مجوز متخصص:** وضعیت `مجوز بازگشت به فعالیت` یا `محدودیت فعال متخصص` ثبت شود ← ورود به مسیر A (با فیلتر سخت) یا C.
2. **رفع خوداظهاری + غربالگری مجدد منفی:** درد گزارش‌نشده برای بازه ‹EXP› و B1 منفی؛ بازگشت به مسیر A به‌صورت «احتیاط» (نه آزاد).
هیچ بازگشت خودکار بدون یکی از این دو.

#### 7.2.7 ارجاع
غیرفوری: توصیه ارزیابی متخصص + نمایش متن بازبینی‌شده؛ فوری: متن اضطراری (EXP-008) و توقف کامل. متن‌ها i18n و بازبینی‌شده.

#### 7.2.8 وضعیت محتوا
قواعد SAF-R2xx (غربالگری ناحیه‌ای) و SAF-R2xx-B (فعالیت محدود) در `draft_unreviewed`. تا تأیید: کاربر واقعی همواره به B2/B5 هدایت می‌شود (محافظه‌کارانه‌ترین مسیر).

### 7.3 مسیر C — آسیب تشخیص‌داده‌شده/بازتوانی (`blocked_expert`)
- فقط برنامه/پروتکل ثبت‌شده توسط متخصص **احراز شده** (EXP-005، DEC-120).
- سیستم صرفاً نمایش، زمان‌بندی و ثبت می‌کند؛ هرگونه تغییر خودکار بار/دامنه/دوز/مرحله ممنوع است.
- هر پروتکل: `protocol_versions`، `eligibility_rules`، مراحل، معیار پیشرفت، امضای متخصص.
- تا تأیید (DEC-008): هیچ پروتکلی `published` نمی‌شود؛ UI مسیر C را غیرفعال و پیام «نیازمند مراجعه به متخصص» نشان می‌دهد.

## 8. حالت محافظه‌کارانه (تا تأیید محتوای بالینی)
تا زمانی که قواعد EXP منتشر نشده‌اند:
1. هیچ برنامه‌ای برای کاربر **واقعی** نمایش داده نمی‌شود مگر آنکه: غربالگری هشدار با متن/فهرست تأییدشده فعال باشد.
2. در محیط توسعه/Staging برنامه‌ها با برچسب «غیرمصوب—فقط آزمایشی» تولید می‌شوند.
3. UI هیچ ادعایی نمی‌کند که قواعد بالینی تأیید شده‌اند.

## 9. الگوریتم جایگزین حرکت
ورودی: حرکت مسدودشده M، کاربر U، زمینه C.
1. نامزدها = `exercise_alternatives(M)` ∪ رگرسیون‌های M.
2. حذف نامزدهایی که `review_status ≠ published`.
3. اعمال تمام فیلترهای §5 بر هر نامزد.
4. اعمال تطبیق: هدف، محدودیت، تجهیزات، سطح مهارت، بار، دامنه، علائم، سطح شواهد.
5. رتبه‌بندی با امتیاز قطعی (وزن‌های پیکربندی، مستند در سند 11).
6. اگر مجموعه تهی → «جایگزین معتبر وجود ندارد» + (در صورت لزوم) ارجاع. حدس ممنوع.
7. هر جایگزین با `reason_codes` ثبت می‌شود.

|---|---|
| زیر ۱۸ | مسدود (SAF-R001) |
| بارداری | `BLOCK_OUT_OF_SCOPE` + ارجاع؛ ثبت `needs_professional_clearance` |
| بیماری پیچیده/پرخطر | همان؛ فهرست توسط EXP-004 |
| سالمند پرخطر | همان (تعریف توسط EXP-004) |

## 13. ممیزی و ثبت
- جدول `safety_decisions`: decision_id، user_id، status، reason_codes، rule_set_version، inputs_hash، timestamp، actor (سیستم/متخصص).
- جدول `red_flag_events`: رخداد، شدت، ارجاع نمایش‌داده‌شده.
- بازتولیدپذیری: با `inputs_hash + rule_set_version` تصمیم قابل بازتولید است.
- لاگ‌ها بدون داده سلامت غیرضروری.

## 14. گردش حاکمیت محتوای ایمنی
```
Draft → Scientific Review → Clinical Safety Review → (Translation FA/EN) → Publish (versioned)
      → Periodic Review → Rollback ممکن
```
| نقش | مسئولیت |
|---|---|
| Content Admin | نگارش |
| Exercise Reviewer | بازبینی حرکت |
| Nutrition Reviewer | تغذیه |
| Clinical Safety Reviewer | قوانین ایمنی/بالینی |
| Super Admin | بدون حق انتشار قواعد بالینی بدون Reviewer |

قواعد:
- انتشار قاعده ایمنی نیازمند امضای Clinical Safety Reviewer (دو نفره برای severity=critical، پیشنهاد).
- هر نسخه قانون تغییرناپذیر؛ تغییر = نسخه جدید.
- Rollback نسخه با ثبت علت.
- تأیید فهرست‌های EXP مستلزم ثبت: نام بازبین، صلاحیت، تاریخ، منابع. هیچ منبعی جعل نمی‌شود؛ تا ثبت منبع، `source_ref=NULL` و قاعده قابل انتشار نیست.

## 15. کنترل ادعا و متن‌ها
- ممنوع: «درمان می‌کند»، «ترمیم دیسک»، «رفع آسیب»، تشخیص.
- متن هشدار/ارجاع: ترجمه FA/EN با بازبینی EXP-008.
- Disclaimer جایگزین طراحی ایمن نیست؛ بررسی حقوقی DEC-111.
