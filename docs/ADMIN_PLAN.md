# طرح پنل مدیریت (ادمین)

> وضعیت: **مرحله ۱ و مدیریت ادمین‌ها پیاده‌سازی شد** (کنترل رسانه، آپلود عکس، لینک ویدیو، نقش مدیریت/ادمین، گزارش تغییرات، اطلاعیه‌ی سایت `/admin/announcement`، فهرست حساب‌ها با ایمیل ناقص `/admin/users`، ساخت مدیریت با `ADMIN_BOOTSTRAP_EMAIL`). مراحل ۲ تا ۵ هنوز طرح‌اند. اولویت امنیت: فقط نقش `admin` (و نقش‌های بازبین برای بخش خودشان)، همه‌ی تغییرات با ثبت در لاگ ممیزی، و پنل هرگز مسیر تأیید ایمنی (Safety Core) را دور نمی‌زند.

## نقش‌ها (پیاده‌شده)
- **مدیریت** (`super_admin`، فقط یک نفر): همه‌ی کارهای ادمین + افزودن/حذف ادمین + خواندن گزارش تغییرات. ساخت: `python manage.py create_staff --email ... --password ... --role super_admin` (دومی رد می‌شود).
- **ادمین** (`admin`، چند نفر): مدیریت رسانه‌ی حرکت‌ها. فقط مدیریت از صفحه‌ی `/admin/staff` حساب تأییدشده‌ی موجود را ادمین می‌کند.
- نقش‌های بازبین هرگز از اینجا تغییر نمی‌کنند. عکس فقط با آپلود فایل (PNG/JPEG/WebP، تا ۳۰۰ کیلوبایت، با بررسی محتوای واقعی)، ویدیو با لینک یوتیوب.
- صفحه‌ها: `/admin`، `/admin/media`، `/admin/staff`؛ مسیرهای API در `backend/app_services/admin_panel.py` (خارج از OpenAPI).

## اصل‌ها
- پایه‌ی موجود: نقش‌ها (`admin`، `content_admin`، `exercise_reviewer`، …)، دستور `create_staff`، صفحه‌ی `/admin/review`.
- مدیریت محتوا یعنی **نمایش/پنهان‌سازی و انتخاب رسانه**؛ ادمین نمی‌تواند حرکتی را «تأییدشده‌ی ایمنی» کند. تأیید فقط با Safety Core و بازبین انسانی است.
- هر تغییر: چه کسی، چه زمانی، مقدار قبلی/بعدی (قابل بازگشت).

## مرحله ۱ — کنترل رسانه‌ی حرکت‌ها (اولویت)
برای هر حرکت یک «بازنویسی رسانه» ذخیره می‌شود:
- روشن/خاموش: عکس مرجع، ویدیو، انیمیشن ۳D
- نمای پیش‌فرض (عکس / ویدیو / ۳D)
- جایگزینی ویدیو (شناسه‌ی یوتیوب) یا عکس (آدرس/آپلود) و منبع/مجوز آن
- علامت «بازبینی‌شده» با توضیح (مثلاً «۳D این حرکت خوب است»)
صفحه: جدول همه‌ی ۲۲۹ حرکت با پیش‌نمایش سه رسانه کنار هم، فیلتر (بدون عکس، ۳D بازبینی‌نشده، …)، عملیات گروهی.
برنامه فقط رسانه‌ی روشن را به کاربر نشان می‌دهد.

## مرحله ۲ — مدیریت حرکت‌ها و تمرین‌ها
> **تصمیم:** حرکت‌ها از قبل مسیر پیش‌نویس ← بازبینی ← انتشار با Safety Core و بازبین دارند. ویرایش متن حرکت از پنل ادمین آن مسیر را دور می‌زد، پس ساخته نشد؛ تغییر محتوای حرکت فقط از همان مسیر بازبینی انجام می‌شود.
- ویرایش نام فارسی/انگلیسی، توضیح اجرا، عضلات، تجهیزات، سطح، منع‌ها
- افزودن/غیرفعال‌کردن حرکت (انتشار بالینی فقط با بازبین)
- پیش‌نمایش اثر تغییر روی برنامه‌ی نمونه

## مرحله ۳ — تغذیه و غذاها
- ویرایش/غیرفعال‌سازی غذا و مقادیر مغذی (با منبع؛ مقدار ساختگی ممنوع)
- نام‌های فارسی لیست خرید، ایمپورت FDC

## مرحله ۴ — کاربران و دسترسی
- فهرست کاربران، نقش‌ها، غیرفعال‌سازی، بازنشانی تأیید
- دعوت/تعیین نقش بازبین‌ها

## مرحله ۵ — تنظیمات و عملیات
- پرچم‌های ویژگی (روشن/خاموش کردن بخش‌ها)، بنر نسخه‌ی نمایشی، متن اعلان‌ها
- لاگ ممیزی، آمار استفاده (بدون داده‌ی سلامت خام)، وضعیت سلامت سرویس‌ها، پشتیبان‌گیری
- گزارش خطاهای کاربران و صف بازخورد

## فنی (خلاصه)
- بک‌اند: مدل `MediaOverride` + `AuditLog`، مسیرهای `/api/v1/admin/...` با بررسی نقش، سرشماری در OpenAPI و تایپ‌های تولیدشده.
- فرانت: `/admin/*` پشت نقش؛ فایل‌های `public/exercise-media/*.json` فقط مقدار پیش‌فرض‌اند و بازنویسی ادمین از API می‌آید.
- آزمون: دسترسی غیرمجاز (۴۰۳)، ثبت ممیزی، اینکه رسانه‌ی خاموش نمایش داده نمی‌شود، و اینکه ادمین نمی‌تواند ایمنی را دور بزند.

## تصمیم‌های لازم از مالک
۱. ذخیره‌ی عکس/ویدیوی آپلودی: فقط لینک، یا فایل (نیاز به فضای ذخیره‌سازی)؟ ۲. چند ادمین؟ ۳. اول مرحله‌ی ۱ شروع شود؟
